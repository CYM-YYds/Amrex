# 脚本生命周期管理

少量长期工具认真维护，AI 临时脚本及时退出。默认优先清理，不把每次维护变成工具库重构。
日常创建与归属由仓库规则负责，本 Skill 负责分类、清理及必要的整合。
不增加自动扫描器、评分程序或定时删除任务。

## 范围与授权

先读生效的仓库规则和[脚本归属约定](../../../README.md#脚本归属与生命周期)，检查
Git 状态及相关 diff。按用户指定目录或当前明确算例开展，不扩展到其他算例或第三方源码。

- 只要求审查时只读，直接回复结果，不生成维护报告文件或提交。
- 要求清理时，可以执行仓库日常规则已授权的 AI 临时脚本清理；先列候选，再逐文件检查。
  其余删除、迁移、接口变化和功能合并，先提供具体文件与目标方案，取得确认后实施。
- 已确认的范围不重复询问；证据不足的文件保留并说明缺口，不阻塞其他已授权条目。
- 本 Skill 的修改请求不等于授权清理仓库；用户已有修改及来源不明的临时文件不覆盖、不删除。

## 先判断是否需要长期保留

谁使用是默认线索，实际用途决定去留：

| 类型 | 依据与处理 |
|---|---|
| 用户长期工具 | 用户明确在用或要求保留；作为持久工具维护，在所属 README 说明用法。用户使用的事实不自动授权重构 |
| AI 临时脚本 | 当前任务临时创建的检查、调试、数据对比等；任务已完成且无后续依赖时优先删除，不先参数化、写测试或归档 |
| 科研复现材料 | 是关键图表、指标或实验唯一的生成方法，或承载独立数值对照；即使只由 AI 使用，也保留或提出归档方案 |
| 正式内部依赖 | 被现役工具、构建、提交、Skill 或回归测试依赖；即使只由 AI 调用，也随对应工具维护 |
| 用途未知 | 查直接调用与关联结果，仍不明则保留，明确待确认问题，不仅因没有引用或年代久远而删除 |

“可能通用”不构成持久化理由；用户长期工具不要求都放入 persistent 目录。
旧脚本不能仅凭文件名、创建者、所在目录或提交时间判定为 AI 临时脚本。

## 轻量审查与清理

1. 列出范围内脚本，包括平铺的 `scripts/`、`data_post_processing/` 及临时目录中的
   已跟踪与未跟踪文件。报告覆盖范围和盲区，不默认它们已经按生命周期分类。
2. 对 AI 临时候选只检查去留所需证据：任务是否结束，是否仍被 source/import/exec、
   构建/提交/测试或文档命令使用，是否有进行中的任务或作业依赖，是否是关键结果的唯一复现入口。
   不执行未知脚本来探测用途，不为普通临时检查脚本重建完整历史实验。
3. 结果可分为 KEEP、DELETE、REVIEW；只有发现真实长期需求或重复维护成本时，才提出
   PROMOTE、MERGE、ARCHIVE。完整列出已评估文件及理由，允许同类文件合并描述并列出路径，
   不要求每个文件都写长篇分析，也不用“其余保留”掩盖未评估项。
4. 满足已授权条件的临时脚本直接清理。其余方案说明精确源路径、目标、调用者、保留差异和
   验证范围，等待确认；不为减少数量强行合并无关职责，不把全部旧脚本先归档一遍。

只有重构请求或实际重复维护问题才深入比较算法、接口和模块边界。优先扩展现有长期工具，
参数变化优先用参数/配置表达；不增加仅转发调用的 wrapper，不引入推测未来复用的公共层。

## 验证按操作选择

先确定本次改变什么，再选能验证该变化的最小检查；不默认建立基线、重放所有历史实验。

| 操作 | 必要验证 |
|---|---|
| 删除独立 AI 临时脚本 | 核对授权、完成状态、引用及复现例外；检查最终 diff，无需运行被删脚本、重新生成图表或新增测试 |
| 原样移动/归档 | 检查相对路径、import/source、工作目录与权限；只有受影响调用链需要小样本运行。未恢复的历史环境注明限制 |
| 纯文档或不改变行为的格式整理 | 检查相关链接、路径及语言语法，不扩大到数值回归 |
| 修改 CLI 或调用路径 | 语言语法、帮助/参数检查及受影响入口的一个代表性调用；确认原有输入输出契约 |
| 合并/修改数据计算逻辑 | 用已有小样本比较被改变的关键数值、采样和指标；只在不同分支或差异无法解释时扩大回归 |

使用现有测试优先；仅为长期行为保障有必要时才新增持久测试，不为一次性清理维护测试框架。
验证通过后停止，不重复执行相同检查。小样本发现差异或关键分支未覆盖时再补验证；
需要昂贵环境或缺失输入才能验证的重构暂不执行，保留该项并完成其他条目。
Python 分析与绘图使用根 `.venv/bin/python`，ParaView 读取沿用既有环境。
不能用图片生成成功替代数值比较，也不为脚本维护启动 CFD、提交作业或调用远端导出，除非另有授权。

## 复现与收尾

- 删除 AI 临时脚本不等于删除其输出；运行数据、日志、检查点、图片和报告不在默认清理范围。
- 唯一复现逻辑保留，或在经批准整合后记录输入、步数、代码版本、命令参数、归一化和参考来源。
  已有复现记录直接引用，不重复构建证据链。缺失数据时注明缺口，不声称历史结果已重新验收。
- 更新受影响的 README 和调用者；变更记录与提交遵循仓库规则，不为每个临时文件单独写记录。
- 简短报告实际删除、保留、归档/合并条目、验证与未完成项。报告范围内顶层和总脚本数的变化；
  新增文件也计入，移动不算减少。只有用户要求或发现实质性风险时才展开详细报告。
