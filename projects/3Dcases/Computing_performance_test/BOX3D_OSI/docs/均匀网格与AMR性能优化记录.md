更新日期：2026-10-31。本文汇总已有实测及对应参数，不启动新计算；历史长程/论文数据仍见[MLUPS记录](MLUPS记录.md)。

固定条件：下列性能测试均为三维、FP32（4 Byte）、A100-PCIE-40GB，CUDA 12.8、GCC 11.3、SM80、O3/fast_math。AMReX正式默认采用标准D3Q27 BGK，新增Q19实验采用标准D3Q19密度BGK、grown-Fab OSI、NEE物理边界、C++20及RDC；师兄原版和D3Q27改造副本另列模型/边界差异，不能视为完全相同的求解器。

**这些是各次冻结程序的实测，不是当前HEAD所有优化叠加后的重新测速。** 最近的宏观量/本地ghost复制范围统一（`d12f19d`）仅做数值及输出回归；没有据此新增吞吐量。二维已统一默认策略，但未做性能调优，本文不填二维性能数字。

## 1. 计时与吞吐量口径

- MLUPS = 有效格点更新量 / 墙钟秒数 / 10⁶。均匀网格以有效网格计数，不计ghost/halo；AMR按去除细层覆盖、乘各层子步数的有效更新量计数。
- AMR每个粗步的分子为 `Σ_l 2^l × (N_l − N_{l+1}/8)`，最细层下一层数量为0；本文真实三层布局为95,424,512更新/粗步。它不是所有发射线程数或所有分配单元数。
- AMReX的`MLUPS_total`对应`perf(s).total`，含推进及regrid外围工作，不含初始化、收敛检查、场输出或每步STEP日志。性能应用关闭这些诊断/输出；程序报告的`Total Time`另含初始化等，不能混作稳态分母。
- 吞吐按累计有效更新量/累计时间计算，不对窗口MLUPS取算术平均。多GPU每个窗口取较慢rank的耗时，再累加窗口；表中为全域合计吞吐，**不是每GPU吞吐**。
- 表中ms/步对均匀网格是一个时间步，对AMR是一个粗层步。GPU事件时间与CPU等待有重叠，不相加；减少同步后部分阶段字段为0表示未测量，不表示没有成本。

## 2. 师兄原程序

### 参数

| 参数 | 记录 |
|---|---|
| 原件 | 算例根目录`main_ldc_nee.cu`；实验未改动原件 |
| 格子与碰撞 | 声明D3Q19，实际显式读写q=1…18，q0槽位不参与碰撞推进；不将它称为标准D3Q27 |
| 精度、GPU数 | FP32，1 GPU / 1 rank |
| Re、Ma | 1600、0.1 |
| 特征长度 | `L0=NxT`；改变网格也会改变黏度/tau，不是纯规模扩展测试 |
| OSI与布局 | 一维全数组循环平移，flat SoA，尺寸为编译期常量 |
| 边界 | 外置壁面全路反弹及运动顶盖修正，与AMReX valid边界上的NEE不同 |
| 线程 | 128 threads/block |
| 场输出 | 关闭；每步原有GPU同步保留 |
| 步数与统计 | 每尺寸3000步，剔除前1000步；两轮换序，每尺寸累计4000个稳态步 |
| 节点、作业 | whshare-agent-174，621728 |

采用浮点高精度时间及有效流体格点分母。原逐步整数毫秒计时会向下截断，含halo分母又会抬高数值；原打印的256³约8778、586³约7334 MLUPS不作为本文引用性能。原碰撞核94寄存器/线程、无spill；不能仅据此断言它优于D3Q27核的原因。

副本只补齐缺失CUDA错误检查依赖、将原未初始化的feq[0]设零、停用无效旧CPU计时并缩短运行。碰撞和边界kernel正文与原件逐字节相同。四次运行正常退出；未据此完成原版物理精度或跨模型数值验收。[完整报告及原始材料](../runs/temporary/flat_original/round1/report.md)。

### 双方标准Q19同模型对照（621996）

按用户选择，双方实验副本均采用包含q0的标准密度BGK：rho=Σf，u=Σ(fe)/rho，feq=w·rho·(1+3eu+4.5eu²−1.5u²)。采用AMReX已有ORDER0的19方向和权重；原版师兄代码不改，正式AMReX仍默认Q27。

节点whshare-agent-50，单GPU，有效256³、存储260³、FP32、128线程、Re=1000、U0=0.05（有效Ma约0.08660），每次1200步，report=200，剔除前200步；三轮换序，各模式累计3000稳态步。输出、checkpoint、收敛检查关闭。

AMReX Q19相对同节点Q27吞吐提高48.97%，整步时间减少32.87%；达到师兄标准Q19副本吞吐的93.96%。AMReX整步慢6.42%，但碰撞GPU事件区间略短，较高的边界耗时值得优先检查。双方边界（NEE与反弹）、宏观量写出、OSI寻址、构建及事件收集范围仍不同，不能唯一归因为框架开销。两套Q19碰撞核均127寄存器/线程、无spill，未取得硬件计数器。

AMReX Q19周期/非周期64³多Fab、160步A-B/OSI对照，valid/active逐值差范数均0；师兄副本19分量独立double碰撞及全网格映射/边界检查通过。这不是跨程序全场等价、长期精度、AMR或多GPU Q19验收。[完整报告与冻结材料](../runs/temporary/q19_uniform/round1/report.md)。

## 8. 使用这些数字时的边界

1. 师兄原程序、D3Q27改造副本、AMReX之间模型/边界/编译和计时并不完全相同，适合作工程参照，不给出跨模型的“实现效率百分比”。
2. 单GPU约3680（均匀单Fab）和约2256（固定真实AMR）是不同工作负载的吞吐，不能直接拿比值衡量AMR开销；AMR分子包含各层子循环和去覆盖处理。
3. 数值对照、构建通过和正常退出各有不同含义，不等同于长期精度或收敛。各原始报告给出的验证范围继续适用。
4. 未取得Nsight Compute硬件计数器权限；不能由MLUPS、寄存器或216 B/LUP最低读写量直接断言真实DRAM带宽、occupancy或唯一瓶颈。
5. 参数复现应使用对应job的输入快照和命令行覆盖，不把当前config/inputs的默认值倒填到历史测试。报告内保留对应节点、源、程序指纹、命令与原始日志。

512³补充短测：单次1200步、剔除首200步，whshare-agent-186；默认Arena预留导致连续大块申请失败，设置`amrex.the_arena_init_size=0`后完成，Arena使用高水位34094 MB。窗口仍有下降趋势，不能作为充分重复的峰值；[参数、失败记录及计时范围](../runs/temporary/uniform512/round1/report.md)。
