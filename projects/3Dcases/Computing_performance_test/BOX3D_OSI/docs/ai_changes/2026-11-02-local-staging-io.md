# 512³本地落盘与SHA256转存验证

目的：针对已捕获的DPC writev EIO，在用户授权下验证本地文件系统先写、普通主机内存小块转存共享目录的规避路径。不改求解器/AMReX，复用622850已验证的candidate.ex和对应源，不纳入用户当前AmrCoreLBM_advance.cpp修改。

现有恢复脚本直接在共享cwd运行，不能表达本地临时盘/共享已校验批次的不同生命周期；新增临时uniform512_local_staging.py负责分段恢复、事务式转存与删除本地已验证副本，复用collision_amr/submit.sh模块环境入口。checkpoint_io/submit.sh增加只读环境/本任务临时目录检查模式，不新增重复诊断入口。

只读作业622963：75节点/tmp剩约19GiB、/var/tmp约24GiB，后者为本地ext4；dmesg读取被系统拒绝，未提升权限绕过。622975/622997确认本地进程在wb_wait_for_completion等待写回，无已完成的应用错误，约14GiB checkpoint确实持续落盘。

622970先从静止写32步512³场/checkpoint到/var/tmp独立目录，再普通内存8MiB块转存DPC.partial；每文件fsync、共享读回SHA256相等后，公布批次目录并清理本地副本。第一批20个文件、约16GiB全部校验成功；已从该共享checkpoint恢复64步并完成第二批输出/校验。两批通过才进入正式分段长程，不以第一次复制成功代替恢复验收。

正式计划每12800步一批，共40批，单批本地约16GiB、批次前至少20GiB空闲；共享副本全部保留。下一段实际读取上一份共享checkpoint。转存有界重试，失败保留本地及.partial，记录最后已公布批次。分段初始化、转存和收敛缓存重置有额外开销，不将其总耗时当成原连续求解器基线；正式间隔内的曲线可提取，但连续达标次数不能跨进程冒充保留。

验证：Python AST及Shell语法通过；第一批完整场/checkpoint Header、数据长度与逐文件SHA256验证通过；第二批恢复/转存及正式终态以gate/status/completed记录为准。保留全部输入、源、程序、命令、校验清单及诊断日志。当前方案规避用户态直接大writev，不代表已经确认或修复DPC更底层根因。
