# 碰撞批量发射与精确区域工作表实验

目的：区分减少逐 Fab kernel 启动、裁剪无效线程这两类收益。结论：本次两个 TagVector 候选在固定真实三层布局上稳定变慢，不修改正式碰撞路径。

## 实现与复现

在独立源码快照中加入 `lbm.collision_batch_mode`：0 为原逐 Fab 实现；1 为完整区域 TagVector 批量发射，保留 covered/interface 判断；2 为精确区域 TagVector 批量发射，排除 covered 内部与同层通信可覆盖的 ghost。粗层插值 ghost 保留。A-B 路径不改，充当阶段逐值参考。

复用 TagVector、现有几何 tag（区域/Fab 几何/本地索引/phase slot）和同层 FillBoundary 分类；没有引入新的逐格点物理分类规则。精确区域由原掩码逐行提取，再沿 y/z 合并相同区间。工作表归求解器所有，只保存布局几何及本地索引；原边界缓存重建时统一失效，下一次碰撞懒构建；发射时取得当前数组及 phase shifts。保留先发送源 Fab、后其余 Fab 的通信重叠分组。

材料：[实验目录](../../runs/collision_batch_20261023/)、[候选补丁](../../scripts/temporary/collision_batch_candidate.patch)、[公共实验入口](../../scripts/temporary/test_ghost_collision.sh)、[审计工具](../../scripts/temporary/analyze_ghost_collision.py)。实验目录的 source.diff/git_head.txt 记录实验前工作区（含用户修改），candidate/src 为完整候选快照，build.log 为成功编译日志。用户已有正式源码和可执行文件未覆盖、未纳入本次提交。

复现：补丁用 `git apply --unidiff-zero` 应用到实验前源码快照，在独立目录用根 scripts/compile.sh 编译。提交实验目录 submit.sh（COLLISION_TEST=1）；submit_checks.sh 额外设置 GHOST_TEST_MODE=checks，仅做阶段验证。环境变量 GHOST_TEST_MODE=timing 可只做计时。原 ghost 实验入口保持兼容。作业目录均冻结程序、输入、指纹、命令、原始日志和提交脚本；这些脚本/补丁为实验材料，不是生产工具。

## 验证

job617902 的初轮阶段检查为32步，但既有 regrid_fixture 尚未激活 level2，因此不把它当作完整三层验证。真实 step256000 checkpoint 的逐值对照已包含 level0/1/2，推进32步至256032：模式1、2相对模式0，各层 valid/active DDF 最大误差均为0，global linf/l1/l2=0。所有真实对照应用正常结束，结果在 real_b0/1/2。

job617903 将阶段验证延至64步，regrid_int=16、基础32³、最高level2、max_grid_size=16、BF8；模式1/2 × 插值0/1/2 × 单/双rank × 非周期/全周期，共24组。复用 A-B 阶段比较及实际迁移源分类检查，覆盖真实激活的 level2 和两次细步。

双rank非周期物理域外 source 仍存在既有 A-B 差异，单独统计，不宣称所有 ghost 一致。此前同源码关闭裁剪的对照 job617899 有同样现象；本实验主要判定 valid 阶段与内部迁移源，并以真实 checkpoint 的同程序三方案对照补充数值证据。24组均正常结束，39720条阶段检查最大linf=0，4752条迁移源检查的内部ghost mismatch均为0；双rank非周期物理mismatch计数与job617899逐组相同。完整统计见 job617903/audit.json。

## 固定真实网格性能

job617902：whshare-agent-192，A100-PCIE-40GB，单rank/GPU0，同程序同输入，从615364的step256000 checkpoint 各自运行640步至256640。固定原网格，BF32，regrid_int=-1；关闭输出/checkpoint/收敛/OSI细分计时。按0/1/2/2/1/0交替，各模式两次。每160步一个窗口，排除每次首窗口（含首次工作表构建），每模式剩6个稳态窗口。所有6次应用正常结束。不是动态重网格或双rank性能结论，也不与历史615364作跨节点加速比。

正反顺序均支持变慢，远大于波动。计时/调用量与模式1原区域工作量相同；模式2发射量按裁剪集合降低，不以 launch_MLUPS 判优，三模式有效更新量分子相同。

| 层 | 原区域数→裁剪区域数 | 单次发射格点数：完整→裁剪 | 发射减少 | 碰撞时间(s)，0/1/2 |

| L0 | 1→6 | 2097152→1618448 | 22.83% | 0.119286 / 0.138384 / 0.123863 |
| L1 | 10→50 | 4441392→2877912 | 35.20% | 0.482697 / 0.545061 / 0.443331 |
| L2 | 33→103 | 13034960→12287544 | 5.73% | 3.328125 / 3.669556 / 3.740140 |

裁剪使L1比原实现快约8.2%，但主耗时L2慢约12.4%。TagVector避免按每个区域发射，却增加tag查找、数组间接访问及坐标恢复；碎片区域可能影响访问对齐/warp效率，这一硬件原因未用profiler定量确认。ptxas显示原OSI内核198寄存器，完整/裁剪批量208/210寄存器，均无spill；不能仅凭寄存器数推断occupancy下降。仅减少kernel次数或无效线程数不足以预测端到端收益。

未采纳生产改动；保留完整实验证据。后续若继续，应另测按CUDA block预分配区域的任务表或分层混合策略，而非直接推广本次TagVector结果为所有工作表实现的结论。
