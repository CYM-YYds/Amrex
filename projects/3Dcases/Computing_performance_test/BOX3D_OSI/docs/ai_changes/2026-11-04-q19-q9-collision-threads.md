# D3Q19 / D2Q9 碰撞线程数验证

目的：验证当前 FLOAT OSI 碰撞的128线程/block策略在D3Q19与D2Q9下是否仍优。只改变碰撞启动的block大小，不改变坐标复用、公式、其他核或正式默认配置。

## 方法与范围

在 `runs/temporary/collision_threads/round1/` 冻结当前源码、配置、工作树diff和程序；三维实验副本将 `LBM_Q` 从27改为19，二维仍为9。正式源码不变。两个碰撞启动分支在实验副本展开64/128/256/512四个编译期实例，以实验参数选择；同模型使用同一程序。未新增正式参数、缓存或替代路径。

新临时入口 [experiment.py](../../scripts/temporary/collision_threads/experiment.py) 服务本次双模型扫描：既有collision_amr入口固定前轮Q27策略/作业，q19_uniform入口比较不同求解器，均无同程序block-size矩阵；本轮复用现有guard_run.py及MPI模块/启动约定，不扩展正式运行入口。脚本及实验副本保留供复现。

- job626009，whshare-agent-92，单rank、单张A100-PCIE-40GB，CUDA12.8、GCC11.3、HMPI1.2，FLOAT。
- 同模型同网格三轮换序：64/128/256/512、反序、128/512/64/256。
- 均匀网格：D3Q19为256³，D2Q9为2048²；600步，每100步统计，排除首100步。使用nomask碰撞和uniform reduced-sync；另记录CUDA event碰撞时间。
- 动态AMR：D3Q19基础64³，D2Q9基础256²，最高level=2，regrid_int=32，Re=1000，lbm.err=0.125/0.25/0.5/1；320步，每80步统计，排除首80步。保留masked碰撞。
- `perf(s).total` 为完整推进累计时间，含重网格、不含初始化；关闭场输出/checkpoint和嵌套细分计时。
- 每个模型各做单层与动态三层80步seed-pattern检查，以128线程checkpoint作参考，64/256/512共12组比较。检查时统一在末步ComputeMacro触发粗层平均后保存/对照，避免covered粗层阶段错配。

## 三轮扫描结果

完整推进秒数中位数；同一行越小越快。不同模型、不同网格不作绝对性能归因。

|模型/网格|64线程|128线程|256线程|512线程|
|---|---:|---:|---:|---:|
|D3Q19 均匀|1.560860|**1.549623**|1.595329|1.832571|
|D3Q19 AMR|0.804139|**0.803556**|0.816939|0.883879|
|D2Q9 均匀|0.143105|0.139276|**0.138246**|0.142430|
|D2Q9 AMR|0.187618|0.187419|**0.187179**|0.189963|

D3Q19的128比64/256在均匀网格分别少0.72%/2.87%，AMR少0.072%/1.64%；AMR对64几乎持平。D2Q9均匀网格256比128少0.740%，AMR的微小中位数差异小于轮间波动，不能据其单独选择默认值。

均匀网格CUDA event碰撞ms/step中位数：D3Q19的64/128/256/512分别为2.422190/2.401106/2.494349/2.982785；D2Q9分别为0.243960/0.236184/0.234598/0.243298。该阶段趋势与完整推进相符，不据此推断寄存器、occupancy或DRAM瓶颈。

## D2Q9加长确认

job626017分配到whshare-agent-93，同型号A100，复用job626009的D2Q9程序，128/256同节点五轮交替；独立分析，不与agent-92绝对时间合并。均匀网格6000步排除首1000步；AMR3200步排除首800步，其他条件保持本轮相应工作负载。

|网格|128 total秒中位数 [min,max]|256 total秒中位数 [min,max]|判断|
|---|---:|---:|---|
|均匀|1.397818 [1.396491,1.409643]|1.393741 [1.393033,1.395109]|256五对均较快，中位数少0.292%|
|AMR|1.861901 [1.854595,1.875669]|1.865600 [1.863566,1.872177]|128三对较快、两对较慢，范围重叠|

均匀网格CUDA event碰撞中位数128/256为0.235738933/0.235359847 ms/step，256少0.161%。AMR的collide阶段128五对均较快，中位数0.493954/0.504352秒（少2.06%），但完整推进未形成稳定优势。不可把阶段收益当作整体收益。

## 验证与结论

job626009、626017均SUCCEEDED，共84次有效应用（48次扫描性能、16次数值参考/对照、20次加长确认）。12组DDF对照所有层valid/active L1/L2/Linf均为0；同模型同网格的各轮calls/launch_cells及统计工作量一致。加长轮perf_count也逐窗一致，性能日志无NaN/Inf。两维构建成功，源码逐文件审计确认仅实验碰撞启动与三维Q选择改变；Shell/Python语法与diff检查通过。

失败/排除记录：job625999在副本尚未复制完成时启动，编译前退出；job626000完成D3Q19构建及单层检查，AMR因参考checkpoint处于粗层平均前、最终对照处于平均后而在valid粗层检查退出（active范数为0）。修正检查阶段后job626009全部通过；其D3Q19程序复用job626000已编译程序，逐文件验证候选源码一致，避免仅因检查脚本变化重编。失败作业不进入性能统计，日志保留。

结论限于当前硬件、精度、模型与网格及64/128/256/512候选：D3Q19保持128；D2Q9均匀网格256有很小优势，AMR没有稳定端到端赢家。正式默认仍保留128，不引入按网格特判。此次不证明DOUBLE、多GPU、其他GPU、其他布局、长期精度或收敛性。
