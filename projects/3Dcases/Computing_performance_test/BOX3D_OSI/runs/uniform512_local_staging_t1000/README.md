# 512³本地落盘与校验转存重跑

目的：绕开已捕获的DPC共享存储writev EIO路径。复用622850已验证的恢复程序（SHA固定），不改求解器、AMReX、物理模型或用户当前推进修改。当前正式作业623012；预检622970，单GPU/单rank、FP32 Q27、Re1000、512³ lev0单Fab；目标512000步/t1000。

## 数据路径与所有权

75节点/tmp可用约19GiB、/var/tmp约24GiB，选择独立/var/tmp目录。每批开始检查至少20GiB空闲；仅存当前批次约16GiB的场和checkpoint，不把整次约650GiB数据堆在本地。应用首先写本地ext4盘，正式输出每12800步（t25）一批。

每批成功退出、校验Header时间/组件及数据长度后，使用普通主机缓冲按8MiB块写共享目录的.partial；逐文件fsync并从共享副本重读SHA256，与源数据匹配。每文件最多三次有界重试；全部匹配才原子重命名该批目录。只有完成校验后才删除本地临时副本，任一失败保留本地及.partial现场，并在failure.json记录路径和最后已公布的批次。共享副本、全部checkpoint和场文件永久保留，不受本地清理影响。

下一段从刚公布的共享checkpoint实际读回恢复。分段重启是本轮绕行方案：避免同时占用多批本地盘，也持续验证可恢复性；其初始化/转存开销不同于原连续推进，不作为无诊断性能基线。累计perf.total和含恢复/I/O的整次耗时分开解释。收敛正式间隔12800步、趋势4000步，重启会重置历史缓存/连续达标次数，各段记录须按区间解释，不冒充一次连续收敛停止判据。

## 验证与结果入口

同一作业内先做32步同尺寸本地输出、SHA256转存；再从共享32步checkpoint恢复至64步并再次输出/校验转存。两轮成功写gate.json后才从静止启动正式40段。既有小网格数值/512³显存恢复验证复用，不重复数值核测试。每段限30分钟，整体新段启动限24小时；异常中止仍保留上段已验证checkpoint。

正式成功批次见job623012/stepXXXXXXXX，production/下的场/checkpoint软链仅指向校验通过的共享数据，production/run.log合并正式段日志用于曲线提取；job622970/probe32和probe64仅为预检。status.json表示已公布批次，completed.txt才表示全程与转存结束。

DPC内核日志在当前账户下读取被拒绝，不绕过系统权限；此方案是用户态I/O路径规避，不等于证明共享存储根因已修复。诊断源/输入/命令/完整日志/校验清单均保留，复核以实际job目录的runner.py快照为准。

## 实测门槛与正式切换

622970两轮全部通过：每轮约16GiB，逐文件SHA256完整校验，第二轮从第一轮的共享checkpoint实际恢复并重新输出。第一轮应用I/O耗时456.9秒，本地盘较慢；据此在门槛后终止原9小时保护任务（已公布的两批数据保留），正式623012复用同一程序与门槛，不重复预检，将保护时限放宽到24小时。所有正式批次均从静止按12800步分段计算，初始预检不作为长程前缀。

formal作业首批公布前，大run.log仍在节点本地，job目录local_disk.json记录本地路径；小guard日志在共享目录。每批完成后production/run.log和status.json更新。未公布数据不冒充完整恢复点，full completed.txt出现前不声称完整t1000已结束。
