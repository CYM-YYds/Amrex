# 分离桥接运行层与 ParaView 操作层

目的：避免通信客户端继续承担数据管线、相机与排版算法，保持原单文件部署体验。

- `paraview_bridge_runtime.py` 持有连接、命令队列、GUI 调度、计时器、背景备份和
  热更新生命周期；明确导入操作函数，保留原白名单与协议。
- `paraview_operations.py` 持有五个管线/排版函数、唯一 AMR 算法及背景操作，
  不创建线程或桥接实例。背景备份由运行层唯一持有，传入操作函数更新。
- `build_paraview_client.py` 静态生成原路径 `paraview_bridge_client.py`，作为 Windows
  单文件交付物，不手改。复用原哈希、启动入口与热更新机制，无新增 Windows 依赖。
- 批处理直接加载操作层；独立 Gradient 脚本生成从操作层读取唯一算法。
  打包同步检查及 manifest 拒绝过期生成物，README 与维护说明同步职责和打包命令。

验证：五个原操作函数与拆分前 AST 完全相同；普通回归 30 项通过（9 项跳过），
覆盖启动、计时器、热更新、源码一致性和独立工具同步。编译节点真实 ParaView
回归 9 项完成（7 通过，2 项因未指定 MPI/真实 PlotFile 跳过），包括 AMR 覆盖掩膜、
解析旋转场、现有 Slice 修复、相机、标题间距与导出/预览一致性。退出存在既有 EGL
纹理和 printf 格式警告，返回 0。操作层重组没有新增求解器或数值算法验证主张。

Windows GUI 现场通过原热更新入口升级至版本 16，verification=ready；原连接、
source/view 列表通过现有热更新一致性检查，不重建用户管线，不执行排版操作。
