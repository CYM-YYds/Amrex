# ParaView SSH入口限流与长连接

目的：Windows启动日志明确出现Exceeded MaxStartups；减轻桥接频繁认证的压力，避免把入口拒绝误报为密钥错误。日志只证明入口限流，不能证明限流由本工具造成。

范围：仓库ParaView启动器、桥接传输及对应回归；不修改求解器、数据、GUI场景或SSH服务配置。

改动：后台复用单个SSH进程，通过远端Python逐行JSON/base64传递原有命令/数据，保留stdout与stderr边界；断线丢弃失效连接，后续轮询按4、8、16、32、60秒退避，成功重置。停止后台线程时回收连接和读取线程；不因传输失败重放GUI操作。认证/主机指纹错误停止桥。版本升至28、运行时协议升至2，拒绝旧传输协议热更新，当前窗口不自动改变。

启动器仅在原生命令退出255且stderr明确包含Exceeded MaxStartups时最多重试五次，间隔4、8、16、32、60秒；普通Connection closed不重放，以免重复执行已到达的服务启动命令。保留最后一次原始错误与旧桥文件，纠正下载失败提示。没有修改系统MaxStartups或关闭主机验证。

验证：本地真实子进程测试覆盖长连接复用、二进制数据往返、强制断线后重新连接、资源回收、认证失败分类、轮询退避增长及成功重置；既有注册重试/GUI命令生命周期回归保留。PowerShell tree-sitter语法检查无错误。完整测试与生成物检查结果见下方。原生PowerShell不可用，新增限流重试/认证不重试/参数及stdout保持的原生测试条件跳过，不能宣称Windows启动实测通过。未重启或热更新用户当前窗口；部署需Windows重新下载启动器，下次正常启动生效。

最终检查：62项测试共49项通过、13项条件跳过；生成物一致性检查通过，PowerShell tree-sitter无语法错误，按CRLF行尾约定检查diff通过。原生PowerShell下载未成功，未将语法检查当作Windows运行验收。
