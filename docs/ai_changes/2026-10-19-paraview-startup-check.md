# ParaView 启动桥接自检与跨上下文实例统一

- 目的：连接脚本不能仅因 GUI 进程已启动就显示成功；避免旧会话被误认为新启动成功，以及启动脚本/Shell 不同上下文导致找不到桥或重复创建实例。
- 范围：后处理目录的 PS1、桥客户端、说明和专用测试；保留用户已有 PS1 文件模式变化，不修改求解器或当前 ParaView 窗口。
- 最小调用链：PS1 下载桥并计算 SHA256，生成本次 launch ID → 环境传给 GUI → GUI 主线程执行 inspect → SSH 工作线程原子发布本次专属回执 → PS1 检查 ID、版本、文件哈希、必需能力及连接 URI，全部通过后才显示 Bridge ready。失败保留窗口并抛出错误，默认自检等待 180 秒，不是计算作业运行时限。
- 状态所有权：launch ID 由 PS1 每次生成（手动加载时由客户端生成），回执由该桥的工作线程发布，旧启动不能写入新启动编号文件。GUI 成功判断只在主线程执行后产生；固定 current 仍用于发现，不能替代启动回执。脚本哈希在客户端初始化时读取指定本机文件。版本 2 与 PS1 要求匹配，能力列表由客户端统一声明。
- 生命周期：复用现有计时器和传输队列；应用级 builtins 运行时唯一持有桥实例及原生回调引用。重载先停止可定位的旧运行时/__main__/Shell 实例并等待工作线程退出，失败不继续创建第二实例。没有新增运行中自动更新路径，新版功能在下次启动加载。
- 验证：仓库 .venv 运行 3 个专用集成/回归测试通过，覆盖真实文件注册与回执、无 GUI tick 不得产生成功回执、正确 URI/版本/哈希/能力回传、启动编号隔离、GUI 错误回传、跨上下文运行时一致及旧所有者停止；生成 shell bash -n、Python AST、PowerShell tree-sitter 语法检查、BOM/CRLF、文档链接与暂存 diff 检查通过。GetURI API 已核对安装的 ParaView 5.11 头文件。
- 验证边界：当前节点没有原生 PowerShell/Windows GUI，未宣称 Windows 完整启动通过；需用户更新本机 PS1 后在下次启动验证最终 Bridge ready。当前窗口运行的旧桥未自动替换，也没有为测试关闭用户窗口。
