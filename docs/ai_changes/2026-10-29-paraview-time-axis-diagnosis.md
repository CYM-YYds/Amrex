## 证据与结论

job621375 的 A/B 速度、涡量共 16 份 Header，时间全部为 25、50、75、100，对应求解器步数 3200、6400、9600、12800。没有物理时间 0、1、2、3 的输出。

当前 Windows GUI 的全局 TimeKeeper 当前时间 0，时间值为上述八个值的并集；两个当前视图的 ViewTime 均为 0。

| 读取器 | ID | 当前 TimestepValues |
| --- | --- | --- |
| A 速度 plt_003200* | 10990 | 0、1、2、3 |
| B 速度 plt_003200* | 12996 | 25、50、75、100 |
| A 原生涡量 plt_vort_003200* | 11689 | 25、50、75、100 |

各源 FileNames 均按 step3200/6400/9600/12800 排列。因此 A 速度当前把四个文件提供为合成的序号时间，而其他两个读取器按物理时间提供。全局下拉框是混合时间轴，不是单一帧索引。此前只把 0/1/2/3 解释成序号而未核对全局来源的回答不充分，应以上述现场状态更正。

对 A 速度自身，时间 0 对应其第一个文件（step3200、Header time25）；这不代表全局时间 0 对所有数据源都有相同的物理含义。不能在当前时间轴上不加核对地比较 A/B 同一物理时刻。文件 Header 正常，不能把此问题归为求解器时间输出错误。合成时间由何次导入设置或信息缓存产生，本次未定因。
